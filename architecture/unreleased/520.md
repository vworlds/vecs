- [vecs] Changed: BREAKING CHANGE: `Module` no longer extends `Component` or `Entity`; it is a plain class with `world` and `entity` (its definition entity), constructed by `world.module` before field initializers run. `world.module(A)` returns the module instance, which is not an entity; `world.component(A)` and `mod.entity` return the definition entity. Inside a module, `this.on` / `this.off` / `this.parent` / `this.set` / `this.add` become `this.entity.…`; module scope and `world.scope` take `mod.entity`. Static `vecs_*` hooks, `world.get(A)` / `world.has(A)`, `init(config)` and the reverse-installation disposal order are unchanged; remove hooks receive `(mod.entity, mod)` (#520).
- [vecs] Changed: BREAKING CHANGE: `Component<T>` is a type, `ComponentDeclarations<T> & Entity`, no longer a class: `world.component(C)` returns a plain `Entity` with the `member` / `range` / `unit` / `values` / `description` / `snapshotPolicy` builders and typed `on` / `off`. Replace `instanceof Component` with the new `entity.isComponent`, which reads the `ComponentDef` tag, so a registered `Object` class is a component and an entity used only as a key is not. `EntityClass` is removed; every entity, definitions included, is an `Entity` with one prototype and hidden class (#520).
- [vecs] Added: `ModuleDef`, a local schema tag `world.module` adds to every installed module's definition entity (core modules included), excluded from snapshots and rejected in `networkComponents`. Identify modules with `entity.has(ModuleDef)`; a class registered with `world.component(M)` but never installed is not tagged. Each world registers one more component entity (#520).
- [vecs] Fixed: Recover `physics-pose-out` pose and tick time lost in #496: module installation no longer sends dozens of per-module entity classes through the per-entity mutation path, which had made its call sites megamorphic (#520).
- [vecs] Changed: SpaceRocks migration sites: the one `this.set` in `modifiers/components.ts` becomes `this.entity.set`, `instanceof Component` in `transfer/sets.ts` becomes `isComponent`, and the four guard tests switch `instanceof Component` to `isComponent`, `entity instanceof Module` to `entity.has(ModuleDef)`, and module entity uses to `mod.entity` (#520).
- [vecs] Changed: `ComponentDef` and `ModuleDef` declare `(OnDelete, Throw)` explicitly: destroying either marker's definition while a definition carries it throws (#520).
- [vecs] Fixed: A registered `Object` component class is no longer mistaken for an entity used as a component key: its definition is unregistered on destroy and its instances are captured by subtree snapshots (#520).
- [vecs] Fixed: Every entity initialises `_relationshipDataWrites`, so a deferred `modified` on a relationship no longer gives that entity its own hidden class (#520).
- [vecs-mcp] Changed: Module provenance and `kind: "module"` read `ModuleDef` on definition entities, since modules are no longer entities (#520).
- [vecs-protocol] Changed: `NetworkWorld` rejects `ModuleDef` in `networkComponents`, like `ComponentDef` and `Trait` (#520).
- [repo] Tests: Guard that no exported class of any `@vworlds/*` package extends `Entity` and that plain, definition and module entities, fresh and after every mutation path, share one prototype and V8 hidden class (#520).
