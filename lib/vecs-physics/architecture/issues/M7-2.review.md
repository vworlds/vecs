# M7-2 — Body lifecycle on box2d3-wasm

**Phase:** Critical path (sequential).
**Depends on:** M7-1.

## Goal

Replace the TS-engine body lifecycle with box2d3-wasm body creation,
destruction, and per-field update. After this ticket, `b2BodyId`
allocation is authoritative and all downstream systems that look up a
body by entity (forces, kinematic, mass, sleep, pose sync) can be
rewritten against the WASM world.

The `b2WorldId` itself is created here: `installPhysics` constructs the
world the first time, and `PhysicsBodyLifecycle.enter` is what produces
the first `b2BodyId`.

## Acceptance criteria

1. `installPhysics` builds a `b2WorldId` via
   `b2CreateWorld(b2DefaultWorldDef())`, applying resolved
   `PhysicsOptions` (`gravity`, `restitutionThreshold`,
   `hitEventThreshold`, `contactHertz`, `contactDampingRatio`,
   `contactSpeed`, `maximumLinearSpeed`, `enableSleep`,
   `enableContinuous`) onto the def before the create call. Stores the
   id on `PhysicsState.worldId`.
2. `src/systems/lifecycle.ts` is rewritten as `PhysicsBodyLifecycle`:
   - **Query:** `Body`.
   - **`.enter`** — read `Body`, `Position`, `Rotation`,
     `LinearVelocity`, `AngularVelocity`, and optional tunables
     (`Damping`, `GravityScale`, `MotionLocks`, `Sleep`). Fill a
     `b2DefaultBodyDef()` (translate `BodyType` string enum
     `static|kinematic|dynamic` to the matching b2 constant). Call
     `b2CreateBody(worldId, def)`. Store in `state.bodyByEntity` and
     `state.entityByBody`. Defs are short-lived: built, used,
     `.delete()`'d (via `withAllocated` or try/finally).
   - **`.exit`** — look up `b2BodyId`; call `b2DestroyBody(id)`; drop
     both maps. Box2D cascades shape destruction internally; the shape
     system's `.exit` removes its own maps when the bit clears.
   - **`.update(Body, …)`** — `type` change → `b2Body_SetType`;
     `enabled` → `b2Body_Enable` / `b2Body_Disable`; `bullet` →
     `b2Body_SetBullet`. **`allowFastRotation` is honoured at body
     creation only** (via `b2BodyDef.allowFastRotation`); runtime
     mutation is a no-op for M7-2 because `box2d3-wasm@5.2.0` does not
     expose `b2Body_SetAllowFastRotation`. See the FastRotation note
     under "Carryovers" below.
3. The system entity carries `PhysicsSystemTag` (continuation of
   existing wiring, not new).
4. `src/engine/body.ts` and `src/engine/solver_set.ts` are **stubbed**,
   not deleted. M7-2's only requirement is that the **new** WASM
   lifecycle does not reach into the legacy body-creation surface
   (`createBody`, `destroyBody`, `transferBody`, `bodyTypeToNumber`,
   etc.). The stub may retain whatever symbols the surviving engine
   internals and surviving engine tests still import — these files are
   fully demolished in M7-10, so leaving them broadly compatible until
   then is the goal.
   - The minimum the stub must keep is whatever's needed to make
     `npm run typecheck` and `npm run test` green without modifying
     files outside M7-2's Files touched list. In practice that means:
     - **`engine/body.ts`** retains the body-type / flag / sleep / lock
       constants (`DYNAMIC_BODY`, `STATIC_BODY`, `KINEMATIC_BODY`,
       `DYNAMIC_FLAG`, `LOCK_LINEAR_X`, `LOCK_LINEAR_Y`,
       `LOCK_ANGULAR_Z`, `ALLOW_FAST_ROTATION`, `IS_BULLET`,
       `ENABLE_SLEEP`, …), the storage/type exports the surviving
       engine internals reach for (`BodyStorage`, `BodySim`,
       `BodyState`, `InternalBody`, `makeBodySim`,
       `makeIdentityBodyState`, …), and `writeBodyTransform`.
     - **`engine/solver_set.ts`** retains the set-index constants
       (`AWAKE_SET`, `FIRST_SLEEPING_SET`, `DISABLED_SET`,
       `STATIC_SET`), the storage types
       (`SolverSet`, `createBaseSolverSets`, …), **and**
       `createBody` / `destroyBody` / `transferBody` if any surviving
       test or engine internal still imports them. These helpers will
       be deleted in M7-10 alongside the engine tests that exercise
       them.
   - Add a one-line file header on each: "Transitional stub kept alive
     for surviving engine code; full deletion happens in M7-10."
   - **Strict no-go list** (these are M7-2's actual contract): nothing
     under `src/adapter/`, `src/install.ts`, or the rewritten
     `src/systems/lifecycle.ts` may import from the stubs. Other
     `src/systems/*` files (forces, kinematic, pose*sync*\*,
     mass_recompute, shape_lifecycle, material_filter_sync) are
     unmodified by M7-2 and continue to import what they need from the
     stubs until their owning ticket (M7-5..M7-9) rewrites them.
   - The stub does not need to strip the _bodies_ of retained helpers
     — leaving `createBody` / `destroyBody` / `transferBody` and their
     supporting types intact (reading/writing `state.bodies`,
     `state.solverSets`, etc.) is fine. They are no longer reachable
     from the WASM-driven runtime path, only from engine tests.
5. Body-id allocation order matches Vecs entity creation order on a
   given run (determinism criterion 3 in PLAN.md Part 1).

## box2d3-wasm calls

- `b2DefaultWorldDef()`, `b2CreateWorld(def)` — install.
- `b2DefaultBodyDef()`, `b2CreateBody(worldId, def)` — `.enter`.
- `b2DestroyBody(id)` — `.exit`.
- `b2Body_SetType(id, type)`, `b2Body_Enable(id)`, `b2Body_Disable(id)`,
  `b2Body_SetBullet(id, bool)` — `.update(Body, …)`.
- `b2BodyDef.allowFastRotation` (create-time only). The runtime setter
  is **deliberately omitted** — `box2d3-wasm@5.2.0` does not expose
  `b2Body_SetAllowFastRotation`, so changing `Body.allowFastRotation`
  after creation is a no-op in M7. See FastRotation note under
  "Carryovers" below.
- All `b2DefaultBodyDef()` and `b2DefaultWorldDef()` allocations must
  funnel through `withAllocated` / try-finally `.delete()` (M7-1
  contract).

## Carryovers from M7-1

The M7-1 review surfaced three implementation details the M7-2 coder must
honour — they refine, not override, the acceptance criteria above:

- **Canonical body maps are the `Wasm`-suffixed ones.** The adapter
  `PhysicsState` subclass deliberately uses `bodyByEntityWasm` and
  `entityByBody` (WASM-side) instead of shadowing the parent's
  `bodyByEntity`/`entityByBody` (TS-engine handles). Where this ticket
  says "store in `state.bodyByEntity` and `state.entityByBody`", read
  that as `state.bodyByEntityWasm` and `state.entityByBody` — i.e.
  populate the WASM-suffixed map, not the TS engine's body map. Same
  rule for shapes in M7-3.
- **Swap the `PhysicsState` type import path.** Today, systems
  (including `lifecycle.ts`) import `PhysicsState` as a type from
  `../engine/state.js`. When this ticket swaps `installPhysics` to use
  the adapter's `PhysicsState`, the type import in `lifecycle.ts` (and
  anywhere else that references the type as part of this ticket's
  rewrite) must move to `../adapter/state.js`. Don't reroute imports in
  systems this ticket isn't already rewriting — those are owned by
  later tickets.
- **`preloadPhysics` is already wired into the test runner.** M7-1 added
  `tests/setup.ts` with a shared `beforeAll(async () => { await
preloadPhysics(); })`, registered via `vitest.config.ts` `setupFiles`.
  M7-2 tests can rely on `getBox2D()` returning a loaded module without
  any per-suite setup.

### Spec updates from the M7-2 first-pass blocker

The first coder attempt surfaced three structural problems the original
ticket couldn't accommodate. The AC list and Files-touched section above
have been updated to reflect the resolutions:

- **Stub, don't delete (AC #4).** Hard-deleting `engine/body.ts` and
  `engine/solver_set.ts` cascades through 12 surviving engine internals
  and 7 system files M7-2 isn't authorised to rewrite. The deletion is
  deferred to M7-10. M7-2 strips the body-creation surface from these
  two files and leaves only the constant re-exports surviving code
  depends on. Surviving engine internals (`broad_phase`, `collide`,
  `sleep`, `island`, etc.) must continue to typecheck.
- **Widen the `installPhysicsSystems` signature.** `install.ts`
  constructs `adapter.PhysicsState` and passes it to
  `installPhysicsSystems`, which today is typed for engine
  `PhysicsState`. `lifecycle.ts` (now adapter-typed) won't accept the
  engine type. The drive-by edit to `src/systems/index.ts` (type widen
  only — no logic changes) is authorised by this ticket; see Files
  touched.
- **FastRotation API is missing.** `box2d3-wasm@5.2.0` has no
  `b2Body_SetAllowFastRotation` setter. AC #2 has been amended:
  `allowFastRotation` is honoured only at body creation via
  `b2BodyDef.allowFastRotation`; `.update(Body, …)` ignores it. A
  follow-up note belongs in PLAN.md Part 1 (Body component contract);
  the M7-2 coder is **not** asked to update PLAN.md — flag it in the
  closing report as a deferred docs fix.
