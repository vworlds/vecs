### PLAN.md Part 1 docs mismatches (fix in this ticket)

`PLAN.md` Part 1 documents box2d3-wasm primitives that, in practice
under `box2d3-wasm@5.2.0`, behave differently from what the doc shows.
Each was surfaced during M7-2/M7-4/M7-7/M7-8 and worked around in code;
PLAN.md needs amending so future contributors aren't misled.

Apply these specific corrections to `architecture/PLAN.md` Part 1:

1. **`b2Body_SetAllowFastRotation` is not exposed.** Only the
   create-time `b2BodyDef.allowFastRotation` field exists in
   `box2d3-wasm@5.2.0`. Body component contract: changing
   `Body.allowFastRotation` after creation is a no-op (M7-2 dropped
   runtime mutation). Document this on the `Body` component row in the
   Part 1 defaults table and on the `PhysicsBodyLifecycle` § text.
2. **`b2World_GetBodyEvents` returns `.moveCount` + `.GetMoveEvent(i)`,
   not a `moveEvents` array.** Any pseudocode in Part 1 § _Pose and
   velocity synchronization_ and § _PhysicsPoseSyncOut_ showing a
   `moveEvents` array should be amended to use the `.count` / `.GetEvent
(i)` shape.
3. **`hitEvents` live on `b2ContactEvents`, not `b2BodyEvents`.** Any
   pseudocode in § _Events pipeline_ / § _PhysicsEvents_ that puts hit
   events under `b2World_GetBodyEvents` should move them under
   `b2World_GetContactEvents`. The M7-8 implementation walks
   `hitCount` / `GetHitEvent(i)` on the contact events struct.
4. **`b2World_GetContactEvents` / `b2World_GetSensorEvents` also use
   the `.count` / `.GetEvent(i)` shape** (e.g. `beginCount` /
   `GetBeginEvent(i)`, `endCount` / `GetEndEvent(i)`). Same correction
   to the § _Events pipeline_ pseudocode.
5. **`b2Shape_SetRollingResistance`, `b2Shape_SetTangentSpeed`, and a
   `userMaterialId` setter are not exposed.** Material updates touching
   those fields recreate the shape via `recreateShapeForEntity` (M7-7
   path). Document this on the `Material` row in the Part 1 defaults
   table and in § _Material and filter updates_.

Read the existing Part 1 prose before editing — keep the writing style
consistent. Do not rewrite or condense sections that don't need
amending. Treat this as a docs patch, not a rewrite.
