# M7-7 — Material, filter, sensor, and mass recompute on box2d3-wasm

**Phase:** Parallel band (after M7-4).
**Depends on:** M7-3 (shape ids exist and look up).
**Parallel with:** M7-5, M7-6, M7-8, M7-9.

## Goal

Wire shape-side property updates (`Material`, `CollisionFilter`,
`Sensor`) and body mass recompute to box2d3-wasm setters and the
auto-mass behaviour of `b2Shape_SetDensity`.

## Acceptance criteria

1. `src/systems/material_filter_sync.ts` is rewritten as
   `PhysicsMaterialFilterSync` (phase `physics-pre`):
   - **`.update(Material, …)`** on a shape entity:
     - `density` → `b2Shape_SetDensity(shapeId, density, true)`
       (the `true` flag triggers auto mass-recompute on the parent
       body — covers most of M7-7's mass needs).
     - `friction` → `b2Shape_SetFriction(shapeId, value)`
     - `restitution` → `b2Shape_SetRestitution(shapeId, value)`
     - `rollingResistance` → `b2Shape_SetRollingResistance(shapeId, value)`
     - `tangentSpeed` → corresponding setter.
     - `userMaterialId` → corresponding setter (or recreate if no setter
       is exposed; document which it is in the implementation).
   - **`.update(CollisionFilter, …)`**:
     - Build a `b2Filter` from `categoryBits` (32 bits zero-padded to
       Box2D's 64 bits — see PLAN.md § **Settled decisions**),
       `maskBits` (same widening), `groupIndex`.
     - Call `b2Shape_SetFilter(shapeId, filter)`. Box2D rebuilds the
       affected contacts internally on the next step.
     - `.delete()` the filter object after the set call.
   - **`.update(Sensor, …)`**: v1 implementation is **destroy +
     recreate** the shape with `def.isSensor = true/false`. No runtime
     setter. Coordinate with `PhysicsShapeLifecycle`'s recreate path so
     this does not double-fire.
2. `src/systems/mass_recompute.ts` is rewritten as
   `PhysicsMassRecompute` (phase `physics-pre`):
   - Most cases are no-ops post-M7 because `b2Shape_SetDensity(..., true)`
     auto-recomputes mass.
   - For bodies explicitly marked dirty in `state.dirtyMassBodies` (e.g.
     after a manual flag flip set elsewhere), call
     `b2Body_ApplyMassFromShapes(bodyId)` and clear the dirty set.
3. `dynamic-body-without-density` debug code (PLAN.md debug table) is
   emitted from this system after recompute when a dynamic body's total
   mass is `0`. The body does **not** fall (Box2D keeps `mass = 0,
invMass = 0` for dynamic bodies with no positive-density shapes —
   PLAN.md § **Settled decisions**). Do not auto-fix; debug warn only.
4. `src/engine/mass.ts` is **stubbed**, not deleted (same pattern M7-2..
   M7-4 applied to engine files). The mass-recompute surface used by
   the new WASM path (`PhysicsMassRecompute` reading
   `state.dirtyMassBodies` and calling `b2Body_ApplyMassFromShapes`)
   does not reach into `engine/mass.ts`. The stub may retain whatever
   symbols surviving engine internals and engine tests still import.
   Strict no-go list: nothing under `src/adapter/`, `src/install.ts`,
   the rewritten `src/systems/material_filter_sync.ts`, or the
   rewritten `src/systems/mass_recompute.ts` may import from the stub.
   Other systems may continue to import from it until their owning
   ticket rewrites them. Full deletion lands in M7-10. Add a one-line
   header: "Transitional stub kept alive for surviving engine code;
   full deletion happens in M7-10."

## box2d3-wasm calls

**`PhysicsMaterialFilterSync`:**

- `b2Shape_SetDensity(shapeId, value, true)` — `updateBodyMass = true`
  is the key flag.
- `b2Shape_SetFriction(shapeId, value)`
- `b2Shape_SetRestitution(shapeId, value)`
- `b2Shape_SetRollingResistance(shapeId, value)`
- `b2Shape_SetTangentSpeed(shapeId, value)` (if exposed; else recreate)
- `b2Shape_SetFilter(shapeId, filter)` — filter constructed locally,
  `.delete()`'d after.

**`PhysicsMassRecompute`:**

- `b2Body_ApplyMassFromShapes(bodyId)` — only for entities in
  `state.dirtyMassBodies`.
- `b2Body_GetMass(bodyId)` — for the dynamic-mass-zero debug check.

**PhysicsMassRecompute**, § **Material and filter updates**.

## Carryovers from M7-1..M7-4

The critical-path tickets established four patterns that apply here,
plus one M7-3 should-fix that M7-7 owns the decision on:

- **Read from the WASM-suffixed maps.** Shape lookups use
  `state.shapeByEntityWasm` (eid → `b2ShapeId`) and reverse via
  `state.entityByShape`. Body lookups use `state.bodyByEntityWasm`.
  Do not read from the legacy `state.shapeByEntity` /
  `state.bodyByEntity` maps; they will be removed in M7-10.
- **Verify each box2d3-wasm setter exists in v5.2.0 before committing.**
  Critical for this ticket because the AC lists six shape setters
  (`b2Shape_SetDensity`, `b2Shape_SetFriction`,
  `b2Shape_SetRestitution`, `b2Shape_SetRollingResistance`,
  `b2Shape_SetTangentSpeed`, `b2Shape_SetFilter`) plus
  `b2Body_ApplyMassFromShapes` and `b2Body_GetMass`. The M7-3 reviewer
  already confirmed `b2Shape_SetDensity`, `b2Shape_SetFriction`,
  `b2Shape_SetRestitution`, and `b2Shape_SetFilter` exist (`b2Shape_*`
  setters used by `shape_lifecycle`). Confirm the remaining ones
  (`b2Shape_SetRollingResistance`, `b2Shape_SetTangentSpeed`,
  `userMaterialId` equivalent) before writing the calls. For any
  missing setter, fall back to destroy + recreate via the
  `recreateShapeForEntity` helper M7-3 exported from
  `src/systems/shape_lifecycle.ts`, and flag a PLAN.md docs fix in the
  closing report. Do not ship a feature-detect wrapper.
- **Route the `dynamic-body-without-density` warning through the
  debug system.** M7-3's must-fix established that diagnostic
  warnings flow via `WarnDedupe`. Read `src/systems/debug.ts` first to
  see if the same condition is already emitted there.
- **Pool the `b2Vec2` / `b2Filter`.** `b2Filter` is allocated per
  `.update(CollisionFilter, …)` call. Either funnel through
  `withAllocated`, or pool one `b2Filter` on `state.scratchFilter` (add
  to `adapter/state.ts` and **list `src/adapter/state.ts` under Files
  touched** before starting — M7-4 hit this gate by not pre-amending).
  No allocation per call.
- **Handler duplication with `PhysicsShapeLifecycle` (M7-3
  should-fix).** M7-3's reviewer noted:
  > Material/CollisionFilter/Sensor `.update()` handlers on
  > `PhysicsShapeLifecycle` partially duplicate `PhysicsMaterialFilterSync`.
  > Both systems fire on Material/CollisionFilter/Sensor changes…
  > redundant and may confuse M7-7's implementer. M7-7 should decide
  > whether to remove `shape_lifecycle`'s material/filter update
  > handlers.
  > Recommendation: **remove the duplicate `.update(Material, …)`,
  > `.update(CollisionFilter, …)`, and `.update(Sensor, …)` handlers
  > from `shape_lifecycle.ts`** so `PhysicsMaterialFilterSync` (this
  > ticket's owned system) is the sole consumer of those component
  > updates. If you do, add `src/systems/shape_lifecycle.ts` to Files
  > touched (this is the same "scope widen for justified reason"
  > treatment M7-2 applied to `src/systems/index.ts`). State the
  > decision and rationale in the closing report.
- **Sensor toggle's recreate path.** AC #1's Sensor handling says
  "Coordinate with `PhysicsShapeLifecycle`'s recreate path so this
  does not double-fire." Reuse the `recreateShapeForEntity(state,
entity)` export M7-3 ships from `src/systems/shape_lifecycle.ts` —
  do not duplicate the recreate logic.

## Notes

- 32→64-bit filter widening: only the lower 32 bits are populated; upper
  32 are zero. Document this in a code comment in
  `material_filter_sync.ts` because it's the only place in the codebase
  that crosses the width boundary.
- `Sensor` mass behaviour: sensors contribute to mass/CoM/inertia like
  solid shapes unless `density === 0` (PLAN.md § **Settled decisions**).
  Do not special-case sensor density.
