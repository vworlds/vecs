# M7-7 — Material, filter, sensor, and mass recompute on box2d3-wasm

**Phase:** Parallel band (after M7-4).
**Depends on:** M7-3 (shape ids exist and look up).
**Parallel with:** M7-5, M7-6, M7-8, M7-9.

## Goal

Wire shape-side property updates (`Material`, `CollisionFilter`,
`Sensor`) and body mass recompute to box2d3-wasm setters and the
auto-mass behaviour of `b2Shape_SetDensity`.

## Acceptance criteria

1. `src/systems/material_filter_sync.ts` is rewritten as
   `PhysicsMaterialFilterSync` (phase `physics-pre`):
   - **`.update(Material, …)`** on a shape entity:
     - `density` → `b2Shape_SetDensity(shapeId, density, true)`
       (the `true` flag triggers auto mass-recompute on the parent
       body — covers most of M7-7's mass needs).
     - `friction` → `b2Shape_SetFriction(shapeId, value)`
     - `restitution` → `b2Shape_SetRestitution(shapeId, value)`
     - `rollingResistance` → `b2Shape_SetRollingResistance(shapeId, value)`
     - `tangentSpeed` → corresponding setter.
     - `userMaterialId` → corresponding setter (or recreate if no setter
       is exposed; document which it is in the implementation).
   - **`.update(CollisionFilter, …)`**:
     - Build a `b2Filter` from `categoryBits` (32 bits zero-padded to
       Box2D's 64 bits — see PLAN.md § **Settled decisions**),
       `maskBits` (same widening), `groupIndex`.
     - Call `b2Shape_SetFilter(shapeId, filter)`. Box2D rebuilds the
       affected contacts internally on the next step.
     - `.delete()` the filter object after the set call.
   - **`.update(Sensor, …)`**: v1 implementation is **destroy +
     recreate** the shape with `def.isSensor = true/false`. No runtime
     setter. Coordinate with `PhysicsShapeLifecycle`'s recreate path so
     this does not double-fire.
2. `src/systems/mass_recompute.ts` is rewritten as
   `PhysicsMassRecompute` (phase `physics-pre`):
   - Most cases are no-ops post-M7 because `b2Shape_SetDensity(..., true)`
     auto-recomputes mass.
   - For bodies explicitly marked dirty in `state.dirtyMassBodies` (e.g.
     after a manual flag flip set elsewhere), call
     `b2Body_ApplyMassFromShapes(bodyId)` and clear the dirty set.
3. `dynamic-body-without-density` debug code (PLAN.md debug table) is
   emitted from this system after recompute when a dynamic body's total
   mass is `0`. The body does **not** fall (Box2D keeps `mass = 0,
invMass = 0` for dynamic bodies with no positive-density shapes —
   PLAN.md § **Settled decisions**). Do not auto-fix; debug warn only.
4. `src/engine/mass.ts` is deleted.

## box2d3-wasm calls

**`PhysicsMaterialFilterSync`:**

- `b2Shape_SetDensity(shapeId, value, true)` — `updateBodyMass = true`
  is the key flag.
- `b2Shape_SetFriction(shapeId, value)`
- `b2Shape_SetRestitution(shapeId, value)`
- `b2Shape_SetRollingResistance(shapeId, value)`
- `b2Shape_SetTangentSpeed(shapeId, value)` (if exposed; else recreate)
- `b2Shape_SetFilter(shapeId, filter)` — filter constructed locally,
  `.delete()`'d after.

**`PhysicsMassRecompute`:**

- `b2Body_ApplyMassFromShapes(bodyId)` — only for entities in
  `state.dirtyMassBodies`.
- `b2Body_GetMass(bodyId)` — for the dynamic-mass-zero debug check.

**PhysicsMassRecompute**, § **Material and filter updates**.

## Notes

- 32→64-bit filter widening: only the lower 32 bits are populated; upper
  32 are zero. Document this in a code comment in
  `material_filter_sync.ts` because it's the only place in the codebase
  that crosses the width boundary.
- `Sensor` mass behaviour: sensors contribute to mass/CoM/inertia like
  solid shapes unless `density === 0` (PLAN.md § **Settled decisions**).
  Do not special-case sensor density.
