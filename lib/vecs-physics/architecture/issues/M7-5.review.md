# M7-5 — Forces & impulses on box2d3-wasm

**Phase:** Parallel band (after M7-4).
**Depends on:** M7-2 (body ids exist and look up).
**Parallel with:** M7-6, M7-7, M7-8, M7-9.

## Goal

Wire `Force` / `Torque` accumulation and the hook-driven
`Impulse` / `AngularImpulse` path to box2d3-wasm, plus the post-step
silent zero. After this ticket, all four force-class components match
the public contract on the WASM backend.

## Acceptance criteria

1. `src/systems/forces.ts` is rewritten as `PhysicsForceGather`
   (phase `physics-pre`, non-reactive — re-scans every step):
   - **Query:** `world.filter({ any: [Force, Torque] })` with
     `{ up: [ChildOf, [Body]] }` injecting the immediate parent's
     `Body`. Resolution is shallow: self, then immediate `ChildOf`
     parent, no recursive walk.
   - For each match:
     - `Force` → `b2Body_ApplyForceToCenter(bodyId, { x, y }, wake)`
     - `Torque` → `b2Body_ApplyTorque(bodyId, value, wake)`
   - **No per-step force reset on our side** — `b2World_Step` zeroes
     applied forces internally (matches Box2D).
2. `src/systems/impulse_accumulate.ts` is rewritten as
   `PhysicsImpulseAccumulate`:
   - The system body is a **no-op `.run()`** that exists only to carry
     `PhysicsSystemTag` on the system entity (so silent zero writes
     stay invisible to consumers via source attribution).
   - Hook setup, registered in `installPhysics`:
     `world.component(Impulse).onSet((entity, prev, next) => …)`
     accumulates `next.x`, `next.y` into
     `state.pendingLinearImpulse.get(bodyId)`; tracks `entity` in
     `state.impulseEntitiesThisStep`.
     `world.component(AngularImpulse).onSet(...)` accumulates into
     `state.pendingAngularImpulse.get(bodyId)`.
     Hook resolves the target body via immediate `ChildOf` parent
     fallback (same rule as `Force`).
   - The pre-step drain (called from a pre-step phase system, also
     tagged) flushes `pendingLinearImpulse` via
     `b2Body_ApplyLinearImpulseToCenter(bodyId, vec, wake)` and
     `pendingAngularImpulse` via
     `b2Body_ApplyAngularImpulse(bodyId, value, wake)`, then clears both
     maps. `wake` flag merges as `OR` across queued sets in a step.
3. `src/systems/impulse_zero.ts` is rewritten as `PhysicsImpulseZero`
   (phase `physics-post`, after `PhysicsEvents`):
   ```ts
   for (const entity of state.impulseEntitiesThisStep) {
     const imp = entity.get(Impulse);
     if (imp) {
       imp.x = 0;
       imp.y = 0;
     } // direct write, no modified()
     const ai = entity.get(AngularImpulse);
     if (ai) {
       ai.value = 0;
     }
   }
   state.impulseEntitiesThisStep.clear();
   ```
   The direct writes bypass Vecs's modified-routing entirely. **Do not
   call `modified()`** here — silent-zero needs to be invisible to user
   watchers too, not just to physics systems. `ignoreSource` cannot
   replace this.
4. The "three sets sum correctly" invariant
   (`imp.x = 1; imp.x = 2; imp.x = 3` → applied impulse `6`, not `9`)
   continues to hold because `onSet` fires synchronously inside
   `_notifyComponentSet` after each `Object.assign`, observing each
   set-time value. Asserted by existing tests.

## box2d3-wasm calls

- `b2Body_ApplyForceToCenter(bodyId, vec, wake)` — `PhysicsForceGather`.
- `b2Body_ApplyTorque(bodyId, value, wake)` — `PhysicsForceGather`.
- `b2Body_ApplyLinearImpulseToCenter(bodyId, vec, wake)` — pre-step
  drain.
- `b2Body_ApplyAngularImpulse(bodyId, value, wake)` — pre-step drain.

Vec allocations: use a pooled `b2Vec2` from `PhysicsState` (M7-4
pattern). Do not allocate per-call.

## Carryovers from M7-1..M7-4

The critical-path tickets established four patterns that apply here:

- **Read from the WASM-suffixed maps.** Body lookups use
  `state.bodyByEntityWasm` (eid → `b2BodyId`) and reverse via
  `state.entityByBody` (`b2BodyId` → eid). The legacy
  `state.bodyByEntity` map still exists for un-rewritten engine systems
  but holds engine handles, not `b2BodyId`s; it will be removed in
  M7-10. Do not read from it.
- **Verify each box2d3-wasm setter exists in v5.2.0 before committing.**
  M7-2 discovered `b2Body_SetAllowFastRotation` missing; M7-4
  discovered `b2World_GetBodyEvents` returns `.moveCount` /
  `.GetMoveEvent(i)`, not a `moveEvents` array. Confirm runtime
  signatures for `b2Body_ApplyForceToCenter`, `b2Body_ApplyTorque`,
  `b2Body_ApplyLinearImpulseToCenter`, and `b2Body_ApplyAngularImpulse`
  before writing the calls. Verify in particular that the `wake`
  parameter's semantics match this ticket's "OR-merged across queued
  sets" expectation — if Box2D's `wake` is a per-call flag with no
  internal accumulation, that's fine because the last enqueued value
  in a step is what reaches the setter. Flag any mismatch in the
  closing report as a PLAN.md Part 1 docs fix.
- **Route warnings through the debug system, not raw `console.warn`.**
  M7-3's must-fix established that diagnostic warnings flow through
  the debug system's `WarnDedupe`. The `force-without-target` debug
  code (PLAN.md debug table) must be emitted via the debug system's
  existing path. Read `src/systems/debug.ts` first to see whether the
  code is already produced there for the same condition (if so, you
  don't need to emit anything from `PhysicsForceGather`). Don't add a
  raw `console.warn`.
- **Pool the `b2Vec2`, don't allocate per call.** M7-4 added
  `state.scratchVec2: b2Vec2` on the adapter `PhysicsState`. Reuse it
  for `b2Body_ApplyForceToCenter` and `b2Body_ApplyLinearImpulseToCenter`
  position vectors. If you need a second scratch (e.g. one held by a
  hook closure for the impulse pre-step drain), add it to
  `state.scratchVec2_2` and **list `src/adapter/state.ts` under Files
  touched first** — M7-4 hit this exact gate by not pre-amending Files
  touched. If one scratch suffices (drain runs serially in pre-step
  phase), say so in the closing report and skip the extension.

## Notes

- The hook-vs-system distinction is the one v1 exception (PLAN.md §
  **Hooks vs systems**). Do **not** convert `Impulse`/`AngularImpulse`
  to a `.update()` system — that would resum to `9` instead of `6`
  because Vecs reuses the component instance.
- `force-without-target` debug code (PLAN.md debug table) fires when
  the resolution lookup fails. Emit it; don't throw.
