# M7-3 — Shape lifecycle on box2d3-wasm

**Phase:** Critical path (sequential).
**Depends on:** M7-2.

## Goal

Replace the TS-engine shape lifecycle with box2d3-wasm shape creation,
destruction, reparenting, and same-type in-place updates, plus the
shape-pose-via-recreate path. After this ticket, `b2ShapeId` (and
`b2ChainId` for chains) allocation is authoritative.

## Acceptance criteria

1. `src/systems/shape_lifecycle.ts` is rewritten as
   `PhysicsShapeLifecycle`:
   - **Query:** `{ all: [{ any: [Box, Circle, Capsule, Segment, Polygon,
Chain] }, { parent: Body }] }` — one query covers attachment,
     detachment, and reparenting via `TargetTerm` fan-out.
   - **`.enter`** — resolve parent body via `entity.parent(ChildOf)` →
     `state.bodyByEntity`. Build a `b2ShapeDef` from `Material`,
     `CollisionFilter`, `Sensor`, `ShapePosition`, `ShapeRotation`
     (Box2D-aligned defaults; see PLAN.md Part 1 defaults table).
     Dispatch by geometry type (table below). Store `b2ShapeId` in
     `state.shapeByEntity` / `state.entityByShape`; for `Chain`, use
     `state.chainByEntity`.
   - **`.exit`** — `b2DestroyShape(shapeId)` (or `b2DestroyChain` for
     chains). Drop maps.
   - **`.update(<geom>, …)`** — for same-type prop changes where
     box2d3-wasm exposes setters (filter/density/friction/restitution),
     call the setter in place. For shape dimensions (where setters do
     not exist), destroy + recreate.
   - **`.update(ChildOf, …)`** — reparenting between bodies = destroy
     under old parent, recreate under new.
2. `src/systems/shape_pose_sync.ts` is rewritten as
   `PhysicsShapePoseSync`:
   - **`.update(ShapePosition / ShapeRotation, …)`** — destroy + recreate
     the shape under the body with the new local pose (box2d3-wasm shapes
     have no runtime local-pose setter; recreate is the cheap path).
3. Polygon validation (≤ 8 vertices, convex) and chain validation
   (`points.length ≥ 4`) happen at creation time, not on every update.
   Validation failures emit debug codes `polygon-invalid` /
   `chain-too-few-points` via the debug system (M7-1 ships the system;
   the codes are produced here). Do not throw.
4. `world.setExclusiveComponents(Box, Circle, Capsule, Segment, Polygon,
Chain)` continues to be called by `installPhysics` — geometry swaps
   (Box → Circle) flow through `.exit` then `.enter`. This is wiring
   from M7-1; verify it still fires.
5. Geometry def allocations (`b2DefaultShapeDef`, `b2DefaultChainDef`,
   `b2ComputeHull`, intermediate `b2Vec2`s for vertex arrays) funnel
   through `withAllocated` / try-finally `.delete()`.
6. `src/engine/shape.ts`, `src/engine/geometry.ts`,
   `src/engine/dynamic_tree.ts`, `src/engine/broad_phase.ts` are
   **stubbed**, not deleted (same pattern M7-2 applied to
   `engine/body.ts` / `engine/solver_set.ts`). M7-3's only requirement
   is that the **new** WASM shape lifecycle and the rewritten
   `shape_pose_sync` do not reach into the legacy shape-creation
   surface. The stubs may retain whatever symbols the surviving engine
   internals (`engine/collide.ts`, `engine/sleep.ts`, `engine/island.ts`,
   `engine/state.ts`, `engine/ccd.ts`, etc.) and surviving engine tests
   still import. Full deletion lands in M7-10.
   - **Strict no-go list** (M7-3's actual contract): nothing under
     `src/adapter/`, `src/install.ts`, the rewritten
     `src/systems/shape_lifecycle.ts`, or the rewritten
     `src/systems/shape_pose_sync.ts` may import from these stubs.
     Other `src/systems/*` files (forces, kinematic, pose_sync_in /
     pose_sync_out, mass_recompute, material_filter_sync, lifecycle —
     M7-2's WASM lifecycle is already clean) MAY continue importing
     from them until their owning ticket rewrites them. Note:
     `lifecycle.ts` after M7-2 does **not** import from these files,
     and must not start now.
   - Add a one-line file header on each: "Transitional stub kept alive
     for surviving engine code; full deletion happens in M7-10."
   - The stub does not need to strip the _bodies_ of retained helpers
     — leaving the legacy shape/geometry/tree internals intact for
     engine tests is fine. They are no longer reachable from the
     WASM-driven runtime path.
   - If trimming leaves surviving engine internals referencing dropped
     symbols, restore the export rather than silently widening into
     other engine files. If a symbol genuinely can't be supported in
     the stub, surface it in the closing report.

## box2d3-wasm calls

| Geometry      | Call sequence                                                                              |
| ------------- | ------------------------------------------------------------------------------------------ |
| `Box(hx, hy)` | `b2MakeOffsetBox(hx, hy, center, rot)` → `b2CreatePolygonShape(bodyId, shapeDef, polygon)` |
| `Circle`      | `b2CreateCircleShape(bodyId, shapeDef, circleGeom)`                                        |
| `Capsule`     | `b2CreateCapsuleShape(bodyId, shapeDef, capsuleGeom)`                                      |
| `Segment`     | `b2CreateSegmentShape(bodyId, shapeDef, segmentGeom)`                                      |
| `Polygon`     | `b2ComputeHull(points)` → `b2MakePolygon(hull, radius)` → `b2CreatePolygonShape(...)`      |
| `Chain`       | `b2DefaultChainDef()` + filter/material → `b2CreateChain(bodyId, chainDef)`                |

Plus:

- `b2DefaultShapeDef()` — every `.enter`.
- `b2DestroyShape(shapeId)` — `.exit` (non-chain).
- `b2DestroyChain(chainId)` — `.exit` (chain).

## Carryovers from M7-2

M7-2 review surfaced three patterns the M7-3 coder must honour. They
refine, not override, the acceptance criteria above:

- **Dual-map pattern for shapes.** M7-2 established that the WASM body
  lifecycle populates **both** `state.bodyByEntityWasm` /
  `state.entityByBody` (the new WASM-side maps) **and** the legacy
  `state.bodyByEntity` (the engine map), so surviving engine systems
  and tests that read the engine map continue working until M7-10.
  M7-3 must do the same for shapes: `.enter` populates both
  `state.shapeByEntityWasm` / `state.entityByShape` (new) **and**
  `state.shapeByEntity` (legacy engine map). `.exit` drops all three.
  For chains, `state.chainByEntity` is the only map (no engine legacy
  equivalent in scope here).
- **Body-destroy cascade.** M7-2's `PhysicsBodyLifecycle.exit` calls
  `b2DestroyBody(bodyId)`, and Box2D cascades shape destruction
  internally — every shape attached to the body is destroyed by the
  engine, with its `b2ShapeId` invalidated. M7-3's
  `PhysicsShapeLifecycle.exit` must therefore **not** unconditionally
  call `b2DestroyShape(shapeId)` when its parent body has already been
  destroyed in the same step (e.g. via component cascade or explicit
  removal). Concretely: in `.exit`, before calling `b2DestroyShape`,
  check whether the parent body still exists in
  `state.bodyByEntityWasm` (or use `b2Shape_IsValid(shapeId)` if the
  box2d3-wasm API exposes it). If the body is gone, the shape is gone
  too — just drop the maps. The same logic applies to chains:
  `b2DestroyBody` cascades chain destruction as well.
- **API existence check.** Before committing to runtime setters in
  `.update(<geom>, …)` (filter/density/friction/restitution/sensor),
  verify the corresponding `b2Shape_Set*` exists in
  `box2d3-wasm@5.2.0`. M7-2 discovered `b2Body_SetAllowFastRotation`
  is missing despite being in PLAN.md; the same may apply here. For
  any setter that is missing, fall back to destroy + recreate and
  flag it in the closing report as a deferred PLAN.md Part 1 docs
  fix. **Do not** ship a runtime-feature-detect wrapper — pick one
  path and stick to it.

The first-pass M7-2 attempt cost two coder rounds because of a
literal-vs-stub deletion mismatch. AC #6 above has been pre-amended to
"stub" to avoid the same loop.

**Findings:**

The debug system (`debug.ts:127-156`) independently validates these same conditions with deduped warnings, so end-user output is preserved, but shape-lifecycle's warnings are undeduped and bypass the `WarnSink` test hook. Either funnel these through the shared `WarnDedupe` instance (pass it through `PhysicsState`), or remove the lifecycle `console.warn` calls and rely solely on the debug system's independent validation.
- (should-fix) Material/CollisionFilter/Sensor `.update()` handlers on `PhysicsShapeLifecycle` partially duplicate `PhysicsMaterialFilterSync` — `shape_lifecycle.ts:176-186`. Both systems fire on Material/CollisionFilter/Sensor changes. `shape_lifecycle` updates the WASM shape (density/friction/restitution/filter/sensor-recreate) AND the legacy shape record. `material_filter_sync` (material_filter_sync.ts) also updates legacy shape records and handles contact teardown on filter change. The dual update is harmless for now (same values written), but is redundant and may confuse M7-7's implementer. Note in closing report so M7-7 can decide whether to remove shape_lifecycle's material/filter update handlers.
