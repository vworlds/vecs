# M7-9 — Sleep configuration on box2d3-wasm

**Phase:** Parallel band (after M7-4).
**Depends on:** M7-2.
**Parallel with:** M7-5, M7-6, M7-7, M7-8.

## Goal

Replace the TS-engine `installSleepHooks` + per-body sleep config with
box2d3-wasm's built-in sleep. Sleep is now a property of the world and
the body, not a separate subsystem.

## Acceptance criteria

1. `installPhysics` applies the resolved `enableSleep` option to the
   world def before `b2CreateWorld` (this part may already be done in
   M7-2; verify and reuse).
2. `PhysicsBodyLifecycle.enter` (M7-2) honours the `Sleep` component on
   body creation:
   - `Sleep.enabled` → `b2BodyDef.enableSleep`
   - `Sleep.awake` → `b2BodyDef.isAwake`
   - `Sleep.threshold` → `b2BodyDef.sleepThreshold`
3. `PhysicsBodyLifecycle.update(Sleep, …)` reacts to component changes:
   - `enabled` change → `b2Body_EnableSleep(bodyId, bool)`
   - `awake` change → `b2Body_SetAwake(bodyId, bool)`
   - `threshold` change → `b2Body_SetSleepThreshold(bodyId, value)`
     (If `Sleep` updates were not already handled in M7-2, add them here
     and update `PhysicsBodyLifecycle`'s `.update` query accordingly.)
4. The old `installSleepHooks` call site is removed from
   `installPhysics`. Sleep no longer needs an installer — box2d3-wasm
   simulates sleep as part of `b2World_Step`.
5. `src/engine/sleep.ts` is **stubbed**, not deleted (same pattern M7-2..
   M7-4 applied to engine files). The new WASM sleep behaviour does not
   reach into `engine/sleep.ts` at all — sleep is now simulated by
   `b2World_Step` internally, with `Sleep` component changes routed
   through `PhysicsBodyLifecycle.update(Sleep, …)`. The stub may retain
   whatever symbols surviving engine internals and engine tests still
   import (e.g. `engine/state.ts` may still reference sleep-related
   bookkeeping; `tests/sleep/*` and `tests/engine/sleep.test.ts` may
   still exercise the legacy code paths). Strict no-go list: nothing
   under `src/adapter/`, the rewritten `src/install.ts` (post-AC #4 it
   no longer imports `installSleepHooks`), or `src/systems/lifecycle.ts`
   (the existing M7-2 file already does not import from
   `engine/sleep.ts` apart from constants) may newly import from the
   stub. Other systems may continue importing until their owning ticket
   rewrites them. Full deletion lands in M7-10. Add a one-line header:
   "Transitional stub kept alive for surviving engine code; full
   deletion happens in M7-10."

   Note on the `installSleepHooks` import: M7-2's coder restored the
   `installSleepHooks(state)` call in `install.ts` because surviving
   TS-engine code paths still consumed those callbacks. AC #4 of this
   ticket drops that call and the import. After M7-9, `engine/sleep.ts`
   continues to export `installSleepHooks` and other symbols (so engine
   tests and any other consumer keeps compiling), but nothing in the
   M7-WASM runtime path invokes them.

6. `Body.enabled` and `Body.type` bookkeeping (the
   `body_type_enable_bookkeeping` test) continues to behave correctly:
   disabled bodies do not wake on input, type swaps preserve awake
   state correctly. Verify via the test gate below.

### Interaction with M7-2's body lifecycle

M7-2 ships AC #2 with `.update(Body, …)` reacting to body-property
changes. AC #2/#3 here say to honour `Sleep` on body creation and react
to `Sleep` component changes. The M7-2 coder noted "Sleep is honoured
at body creation only" — they applied `b2BodyDef.enableSleep`,
`.isAwake`, `.sleepThreshold` based on the `Sleep` component during
`.enter`. So AC #2 of this ticket is likely **already done** by M7-2 —
verify by reading M7-2's `lifecycle.ts:enter` and confirm the def
fields are populated from `entity.get(Sleep)`. If they are, AC #2
collapses to "verify; no code change". If they aren't, add the missing
field population in `.enter`.

AC #3 (the `.update(Sleep, …)` reactivity) was not in M7-2's scope, so
that needs new code in `lifecycle.ts`.

## Notes

- The post-M7 sleep contract matches Box2D's: bodies sleep when their
  motion drops below `sleepThreshold` for the configured time and
  `enableSleep` is true on both world and body. We don't add a layer.
- `Sleep.awake = true` on a sleeping body wakes it through
  `b2Body_SetAwake`. Don't conflate this with the `wake` flag on
  forces/impulses — those operate on the same underlying call but the
  trigger is different.
