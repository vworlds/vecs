# M7-12 — Debug warning consolidation

**Phase:** Post-M7 cleanup.
**Depends on:** M7-7, M7-11 (both shipped).

## Goal

Resolve the duplicated `dynamic-body-without-density` warning paths and
consolidate per-system `WarnDedupe` instances into a single shared
instance on `PhysicsState`. M7-10 deferred this because choosing
between the two signal sources was a design call.

## Background

After M7-7 landed, the codebase emits the `dynamic-body-without-density`
debug code from two independent code paths:

1. **`src/systems/mass_recompute.ts`** — WASM ground-truth.
   `PhysicsMassRecompute` calls `b2Body_GetMass(bodyId)` after
   `b2Body_ApplyMassFromShapes(bodyId)` and emits the warning when
   `mass === 0`. Owns its own private `WarnDedupe` instance scoped
   inside `installMassRecompute`. Fires after the recompute, so the
   value reflects the simulator's actual state.

2. **`src/systems/debug.ts`** — ECS-side structural check.
   `PhysicsDebugValidation` walks the component graph (`Material` rows
   under a dynamic `Body`) and emits the same code when no shape under
   that body has positive density. Owns the canonical `WarnDedupe`
   instance the rest of the debug system uses. Fires before any step
   runs, so it catches misconfiguration earlier and without side
   effects on the simulator.

Both checks emit the literal string `"dynamic-body-without-density"`.
The signals are subtly different — one is post-step ground-truth, one
is pre-step structural — and both can be useful, but each has its own
`WarnDedupe` instance, so the deduplication only works within each
system. A body that fails both checks generates two warnings; the
intended one-warn-per-(eid, code) contract is broken across systems.

The M7-7 reviewer flagged the duplication as a should-fix. M7-10's
coder explicitly deferred it because the right answer requires
deciding: keep one signal source and drop the other, or keep both and
plumb a shared dedup so the user sees a single warning regardless of
which path catches the body first.

## Recommended approach

Keep both signal sources (they catch different categories of bug — the
structural check is the most useful for new users; the WASM check
covers edge cases like sensor density semantics where the structural
walk could lie). Plumb a single `WarnDedupe` instance through
`PhysicsState` so the cross-system dedup just works.

## Acceptance criteria

1. `state.warn: WarnDedupe` on adapter `PhysicsState`. Initialized in
   the `PhysicsState` constructor (or in `installPhysics` immediately
   after construction, whichever is cleaner). The user-supplied
   `opts.debugSink` (if set) is wired into this instance.
2. Both emit sites (`mass_recompute.ts:10` and `debug.ts:60`) and any
   other system that imports `WarnDedupe` directly are updated to
   read `state.warn` instead of creating a private instance.
3. The two `dynamic-body-without-density` checks both remain (no
   signal-source choice), but only one warning per
   `(eid, "dynamic-body-without-density")` reaches the sink per step
   regardless of which check fires first.
4. Existing debug-system tests pass without changes. A new test
   exercises both paths firing for the same body in the same step and
   asserts a single warn arrives at the sink.

## Files touched

**Modified:**

- `lib/vecs-physics/src/adapter/state.ts` — add `warn` field + wire
  `debugSink` injection.
- `lib/vecs-physics/src/install.ts` — initialize/wire the shared
  `WarnDedupe`.
- `lib/vecs-physics/src/systems/mass_recompute.ts` — drop the private
  `WarnDedupe`, use `state.warn`.
- `lib/vecs-physics/src/systems/debug.ts` — drop the private
  `WarnDedupe`, use `state.warn`. The current debug system creates
  one in `installDebugValidation` — move it to state and read from
  there.
- Any other `WarnDedupe`-importing system surfaced by
  `grep -rn 'new WarnDedupe' lib/vecs-physics/src/systems/`.

**No deletions.** `src/util/warn.ts` (the `WarnDedupe` class itself)
stays.

## Test gates

- `tests/debug/debug_validation.test.ts` and any sibling debug tests —
  green.
- New test under `tests/debug/` exercising both emit paths for the
  same body in one step.
- Full `npm run test` — green.

## Notes

- This finishes the pattern M7-10 started when it moved
  `previouslyTouched` event sets from system closures onto
  `PhysicsState`. State that's logically per-world belongs on the
  world's state object.
- If a future ticket adds a new debug code, it just needs to call
  `state.warn.warnOnce(eid, code, message)` — no new
  infrastructure required.
- Optional follow-up: also consolidate `debugSink` ownership.
  Currently `installPhysics` reads `opts.debugSink` and passes it
  separately to `installDebugValidation`. After this ticket the sink
  could live on `state.warn` and individual systems wouldn't need to
  know about it at all.
