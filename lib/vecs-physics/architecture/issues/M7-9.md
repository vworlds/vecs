# M7-9 — Sleep configuration on box2d3-wasm

**Phase:** Parallel band (after M7-4).
**Depends on:** M7-2.
**Parallel with:** M7-5, M7-6, M7-7, M7-8.

## Goal

Replace the TS-engine `installSleepHooks` + per-body sleep config with
box2d3-wasm's built-in sleep. Sleep is now a property of the world and
the body, not a separate subsystem.

## Acceptance criteria

1. `installPhysics` applies the resolved `enableSleep` option to the
   world def before `b2CreateWorld` (this part may already be done in
   M7-2; verify and reuse).
2. `PhysicsBodyLifecycle.enter` (M7-2) honours the `Sleep` component on
   body creation:
   - `Sleep.enabled` → `b2BodyDef.enableSleep`
   - `Sleep.awake` → `b2BodyDef.isAwake`
   - `Sleep.threshold` → `b2BodyDef.sleepThreshold`
3. `PhysicsBodyLifecycle.update(Sleep, …)` reacts to component changes:
   - `enabled` change → `b2Body_EnableSleep(bodyId, bool)`
   - `awake` change → `b2Body_SetAwake(bodyId, bool)`
   - `threshold` change → `b2Body_SetSleepThreshold(bodyId, value)`
     (If `Sleep` updates were not already handled in M7-2, add them here
     and update `PhysicsBodyLifecycle`'s `.update` query accordingly.)
4. The old `installSleepHooks` call site is removed from
   `installPhysics`. Sleep no longer needs an installer — box2d3-wasm
   simulates sleep as part of `b2World_Step`.
5. `src/engine/sleep.ts` is deleted.
6. `Body.enabled` and `Body.type` bookkeeping (the
   `body_type_enable_bookkeeping` test) continues to behave correctly:
   disabled bodies do not wake on input, type swaps preserve awake
   state correctly. Verify via the test gate below.

  `b2CreateBody`.

On `Sleep` update:

- `b2Body_EnableSleep(bodyId, bool)`
- `b2Body_SetAwake(bodyId, bool)`
- `b2Body_SetSleepThreshold(bodyId, value)`

## Notes

- The post-M7 sleep contract matches Box2D's: bodies sleep when their
  motion drops below `sleepThreshold` for the configured time and
  `enableSleep` is true on both world and body. We don't add a layer.
- `Sleep.awake = true` on a sleeping body wakes it through
  `b2Body_SetAwake`. Don't conflate this with the `wake` flag on
  forces/impulses — those operate on the same underlying call but the
  trigger is different.
